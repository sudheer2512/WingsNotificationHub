Part 3

Content and automation

Write messages, decide when they go out and to whom, and keep every recipient's choices respected.

    Templates

    A template holds the wording of one message, for one channel and one language. Every change creates a version, and a second person approves it before it goes live.

    Who can do this: template designers and platform, tenant, company and application administrators edit. Template approvers and platform, tenant and company administrators approve, activate and retire. Campaign managers and auditors can read. Operators do not see this screen.

    Finding a template

    The tree on the left runs from tenant to company, application, category and template. A company or application template overrides the tenant-wide one for that scope.

    • Use Search templates to match a code, name or channel.
    • Tick Show empty scopes to see companies and applications that have no templates yet.
    • Each template shows its status: Draft In review Approved Active Retired Rejected.

    Creating a template

    1. Select New template. If you selected a place in the tree first, the scope is filled in for you.
    2. Choose the Tenant, Company and Application. Leave All companies (tenant-wide) and All applications to share it.
    3. Enter a Code, such as PAYMENT_RECEIPT_V1, which is changed to capitals, and a Name.
    4. Enter a Category to group it in the tree, choose the Channel, and enter the Locale, such as en, hi or ta-IN.
    5. For email, enter a Subject.
    6. Enter a first version in Body. You can polish it in the editor.
    7. Select Create draft. The template opens in the editor as Draft.

    Editing a template

    1. Tree. Select a template to open it.
    2. Save draft and Submit.
    3. More actions: test send, clone, retire.
    4. Format. HTML or plain text; rich text, HTML source or text part.
    5. Toolbar for rich text.
    6. Variable chips insert at the cursor.
    7. Live preview updates as you type.
    8. Sample data feeds the preview.

    To edit a template

    1. Select the template. An orange Unsaved changes chip appears as soon as you edit.
    2. For email, choose HTML or Plain text. For HTML, choose how to work:
      • Rich text: use the toolbar: Bold, Italic, Underline, Heading, Paragraph, Bulleted list, Numbered list, Clear formatting and Link.
      • HTML source: edit the HTML directly.
      • Text part: the plain-text alternative. Leave it empty and the hub generates one from the HTML.
    3. Insert variables with the chips under the editor. Dashed chips are built-in values the hub supplies when sending.
    4. Check Live preview. Change Sample data to try other values. Reset rebuilds it from the variables' sample values.
    5. Enter a Change note, then select Save draft.

    Editing an active template does not affect what is being sent. Saving creates a new draft version, and the active version keeps sending until the new one is approved.

    Links can point to a web address or a variable: in the Insert link box enter https://… or {{PaymentLink | url}}.

    Template HTML cannot contain scripts, event handlers, javascript: links or frames. Saving <script> fails with Template HTML contains a disallowed construct: '<script'.

    Variables and filters

    Variables are placeholders in double braces, such as {{CustomerName}}. The sending application supplies the values. Filters format them: {{Amount | currency:INR}} shows ₹18,400.00.

    • Open Variables to set each one's Required flag, Sample value and Description.
    • A variable you use but have not listed shows used in the content; added as required on save.
    • The preview warns Missing: for a required value with no sample, and Not used by the template: for a sample nothing uses.
    • Built-in variables need no declaring: CompanyName, TenantName, RecipientName, UnsubscribeUrl, CurrentDate.
    • Open Syntax help for the filters and blocks. lists them all.

    Sending a test

    Who can do this: anyone who can edit templates, including template designers.
    1. Select More actions (⋮), then Test send.
    2. Choose the Company, Application and Version.
    3. Enter the test address, which depends on the channel: Email, Mobile (E.164), WhatsApp (E.164) or User id.
    4. Check Variables (JSON), then select Send test.

    Only the active version is delivered. For any other version the dialog says Not active: a rendered preview is returned instead of a delivery. and shows the result. For an active version it shows Accepted as notification … and the delivery's status.

    Rolling back or retiring

    Who can do this: template approvers and platform, tenant and company administrators.

    To roll back to an earlier version

    1. Open the template's Versions tab.
    2. On the earlier Retired version, select Roll back. An Approved version shows Activate instead.
    3. Select Activate to confirm. The current version is retired, and new notifications use the one you chose.

    Past deliveries are not changed: each records the version it used.

    To retire a template

    1. Select More actions (⋮), then Retire template.
    2. Select Retire to confirm.

    Notifications that use a retired template fail until a version is activated again. Check that no rule, schedule or application still uses it. To bring it back, use Roll back on the Versions tab.

    Cloning for a translation

    Translations are separate templates with the same code and a different locale. Cloning is also how you make a company or application override.

    1. Open the template, then select More actions (⋮), Clone / translate.
    2. Change the Locale, such as hi, and the Name. For an override, choose a narrower Company or Application.
    3. Select Clone. A new draft opens. Translate it, then submit it for approval as usual.

    Managing notification types

    A notification type names a kind of message and sets its defaults. Select Notification types at the top of the screen.

    1. To change one, select its row. To add one, select New.
    2. Fill in the Tenant, Application (optional), Code, Name and Category.
    3. Choose the Message class, Default channels, Default template code and Default priority.
    4. Tick the options you need, then select Create or Save.

    SMS templates and DLT

    The editor shows the encoding and length as you type, for example GSM-7 · 123 chars · 1 segment (160/segment). The figure turns red above three segments. Characters outside the GSM-7 set switch the message to UCS-2, which fits only 70 characters per segment, or 67 when split. The preview shows the exact count once variables are filled in.

    For India, enter the DLT content template id in DLT template id (India). The rendered text must match the registered template exactly. The DLT entity id goes on the sender identity ().

    WhatsApp templates

    Messages your business starts on WhatsApp must use a template approved by Meta. Write the body with normal variables: the hub converts them to WhatsApp's numbered placeholders.

    1. Under WhatsApp provider template, enter the Provider template name in lower case with underscores, such as invoice_created_v1, and the Language, such as en_US.
    2. Choose the Category: Utility, Marketing or Authentication.
    3. Optionally set a Header (Text, Image, Document or Video; media headers need a Media URL variable), a Footer, and up to ten buttons: Quick reply, URL or Phone.
    4. Select Save draft.
    5. Select More actions (⋮), then Submit to WhatsApp. Choose the WhatsApp provider account and Version, then Submit. The result appears on the Versions tab as WA: and the status.

    If no WhatsApp account is listed, ask an administrator to add one under Providers. A Mock provider answers The provider account does not support template submission.

    Rule designer

    Rules let your applications report what happened, such as “payment overdue”, and leave the hub to decide who hears about it and how. Each rule reads: when this event happens, and these conditions are true, tell these recipients on these channels.

    Who can do this: platform, tenant, company and application administrators change rules. Template designers and auditors can read rules, and can run a simulation.

    Creating a rule

    1. Select New rule, or open a similar rule and select Duplicate. A copy starts disabled, with (copy) in its name.
    2. Set the Tenant, Company and Application the rule covers.
    3. Enter a Name and the Event type, such as payment.overdue. Suggestions appear as you type.
    4. Choose a Notification type, and set Order (lower runs first).
    5. Leave Enabled on. Tick Stop evaluating later rules when this one matches if this rule should be the last one to run.
    6. Add conditions, recipients and channel actions as described below, then select Save.

    A rule cannot be saved without a name, event type and template. The message is The rule is invalid. Name is required. Event type is required. Every action needs a template code.

    Building conditions

    Conditions decide whether the rule fires. With none, it shows No conditions: always matches. A summary at the top of the panel reads the logic back in one line, such as payload.DaysOverdue ≥ 7 AND (payload.AmountDue > 20000 OR payload.customer.tier in [gold, platinum]).

    1. Choose ALL (AND) or ANY (OR) for the group.
    2. Select Condition. Enter the Field, such as payload.DaysOverdue, choose the Comparison, and enter the Value.
    3. Select Group to nest another AND/OR group. Groups can go up to ten levels deep.
    ComparisonsNotes
    equals, not equal, greater than, greater or equal, less than, less or equalNumbers and true/false compare by type. Put text in quotes to force it, such as "007".
    contains, does not contain, starts with, ends withFor text.
    is one of, is none ofValues are comma-separated, such as gold, platinum.
    exists, does not exist, is empty, is not emptyNo value needed.

    Field paths are dot-separated and ignore case, for example payload.customer.tier or payload.items.0.sku.

    Priority, retry, escalation and quiet hours

    Open these panels under the channel actions when you need them.

    Simulating a rule

    A simulation shows exactly what would happen. Nothing is sent.

    1. Save the rule. Simulation uses saved rules: save first to test your edits.
    2. Under Simulation, choose the Company and Application.
    3. Edit Sample payload (JSON) to resemble a real event.
    4. Tick Only this rule (saved version, even if disabled) to test it alone, or leave it clear to see every rule for the event.
    5. Select Run simulation.

    Rules evaluated shows Matched or No match for each rule. Notifications that would be created lists each delivery, the consent decision, the send time and the rendered text. In the example above, a real event would then go by SMS through the fallback.

    Before switching on a rule, simulate three payloads: one that should match, one that should not, and one customer with no consent.

    To remove a rule, open it and select Delete. Events no longer trigger it.

    Campaigns

    A campaign sends one message to many people at a controlled pace. A manager prepares it, and someone else approves it.

    Who can do this: campaign managers and platform, tenant and company administrators prepare campaigns. Administrators at those levels approve them. Operators, auditors and application administrators can look.

    Creating a campaign

    1. Select New campaign.
    2. Choose the Company and Application, and enter a Name.
    3. Choose the Channels and Template code. The list shows active templates for the channels you chose, and each channel needs one.
    4. Choose the Notification type and Message class. Promotional needs marketing consent and honours unsubscribes.
    5. Set Schedule (local time, optional). Leave it empty to start on approval.
    6. Set Throttle (messages/minute). The default is 600.
    7. Choose who receives it: Recipient groups, a Segment, an imported list, or a mix.
    8. Enter Template variables (one per line: Name=value). Imported columns override these for each recipient.
    9. Select Save draft.

    Importing recipients

    1. Prepare a .csv or .xlsx file with the columns email, mobile, name and externalId, plus a column for each template variable.
    2. Open the draft campaign and select Import recipients.
    3. Choose the file. The result appears at the top of the campaign, for example Import: 5 imported, 1 rejected., with each bad row listed.
    4. Fix the rejected rows and import them in a new file. Imported rows are added to the list.
    email,mobile,name,externalId,CustomerName
anita@example.com,+919800000101,Anita Rao,C-2001,Anita Rao
bharat@example.com,+919800000102,Bharat Shah,C-2002,Bharat Shah

    Each row needs an email, mobile or externalId. A row with only an externalId is accepted, and is Skipped when the campaign runs if it has no usable address. Row numbers count the heading as row 1. A second import adds to the list; repeats in the same file are rejected as duplicate recipient.

    Testing a campaign

    Select Test send on a draft and enter one Recipient email or mobile (E.164). The result appears on the campaign as Test accepted as ….

    The test uses the campaign's Template variables and has no import columns to draw on. If the template needs a value such as CustomerName, add it there, or the test fails with The notification could not be rendered. Consent rules apply to tests too: a promotional test to an address with no marketing consent is accepted but shows Suppressed.

    Submitting and approving

    1. The manager selects Submit, then Confirm. The campaign becomes Pending approval. A campaign with no audience is refused: Add recipients (import, groups or a segment) before submitting.
    2. An approver selects Approve on the campaign, or uses Approvals ().
    3. With a schedule, it waits as Scheduled. Without one, it starts shortly after approval and shows Running.

    You cannot approve a campaign you created: Maker-checker: you created this campaign.

    Following and controlling a campaign

    Select a campaign to see progress, recipient and delivery counts, cost, and a table of recipients you can filter by Status: Pending Queued Skipped Failed. The Error column gives the reason, such as No marketing consent recorded for this channel. Select Open deliveries in explorer to see each delivery.

    ButtonWhat it does
    Pause, ResumeStops and restarts sending at once. Appears while the campaign is Running or Paused.
    Emergency hold, Lift holdHolds pending messages, not lost, and needs a Reason. The campaign shows Suspended beside its status.
    CancelPending deliveries are cancelled. This cannot be undone.

    A small campaign can finish in seconds, before you can pause it. Set a low throttle if you want time to watch one. If a campaign finishes while on hold, it keeps showing Suspended until you select Lift hold, because some of its messages may still be held. Cancelling a campaign clears its hold.

    Recipients

    This screen holds who you can reach and what they agreed to: contacts, preferences, consent, suppressions and groups.

    Who can do this: campaign managers and platform, tenant, company and application administrators change recipients. Auditors read with addresses masked. Operators, designers and approvers do not see this screen.

    Adding and editing contacts

    Your applications normally keep contacts up to date. Use this screen for corrections and one-off additions.

    1. On Contacts, select Add contact.
    2. Choose the Company and Kind: User, Customer or Other.
    3. Enter the External id your application uses, and the Name.
    4. Enter the Email, Mobile (E.164) and WhatsApp (E.164). E.164 means the full international form, such as +919845012345.
    5. Enter the Time zone, Locale, Country and Roles (comma-separated) if you know them. Then select Save.

    To change a contact, use the pencil icon. Company, Kind and External id are fixed. Stored addresses appear as hints: leave a field empty to keep its value. Find contacts with Search (id, name, email or mobile, then Enter), Company and Kind.

    Erasing a person's data

    1. On the contact's row, select the Erase personal data icon.
    2. Read the warning, then tick I understand this is permanent (right to erasure).
    3. Select Erase. You see Personal data erased.

    This cannot be undone. Name, email, phone numbers and attributes are removed, addresses in delivery history are replaced by hashes, message bodies are purged and devices are unregistered. The contact also disappears from the list.

    Preferences and consent

    To change a contact's preferences

    1. On Contacts, select the row or its Preferences and consent icon. The Preferences & consent tab opens.
    2. Use the switches under Channel preferences. Category * applies to every category. A specific category beats *.
    3. To add a category, enter it in Add category and select Add.
    4. Select Save preferences.

    To record consent or a withdrawal

    1. Under Record consent, choose the Channel.
    2. Choose the Purpose: Channel opt-in (needed for WhatsApp) or Marketing.
    3. Choose the Status: Granted or Withdrawn.
    4. Enter the Source, such as web-form, and the Evidence, such as a form or call reference.
    5. Select Record.

    Consent (latest per channel and purpose) shows what applies now. Consent history (append-only) keeps every change, and cannot be edited.

    Suppressions

    A suppression blocks an address, and the hub adds most of them itself when a provider reports a hard bounce, complaint or invalid address. Each one blocks according to the table above.

    To suppress an address

    1. Open Suppressions. Under Add suppression, choose the Tenant and, if it applies, the Company (optional).
    2. Choose the Channel, enter the Address, choose the Reason, and add a Note.
    3. Select Suppress address.

    The suppression applies to the company you chose, or to the whole tenant if you chose Whole tenant. The Scope column shows which, and your Note appears under the Reason. Suppressions the hub adds itself after a bounce or complaint always apply to the whole tenant.

    To remove a suppression

    1. Find it with Channel and Address contains (press Enter).
    2. Select the delete icon, then Remove. Messages to that address are allowed again.

    Groups

    Groups name a set of contacts for rules and campaigns. A Static group lists its members. A Dynamic group works them out from a filter each time.

    1. Open Groups. Under New group, choose the Company, then enter a Name and Description.
    2. For a static group, choose the Members. For a dynamic group, switch on Dynamic (membership from a contact filter) and build the filter as for rule conditions. Fields include kind, externalId, name, email, mobile, country, locale, roles and attributes.<name>.
    3. Select Create group. Select a group in the list to see its members.

    Schedules and holiday calendars

    Schedules send a notification on a repeating pattern or as a series of reminders, in a time zone you choose, and can skip weekends and holidays.

    Who can do this: platform, tenant, company and application administrators create schedules. Campaign managers, operators and auditors can look. Calendars need tenant or platform administrators.

    Creating a schedule

    1. Under New schedule, enter a Name, and choose the Company, Application and Time zone.
    2. Choose the kind:
      • Recurring (cron): enter a Cron expression in the order minute, hour, day, month, weekday. 0 9 1 * * means 09:00 on the first of each month, and 0 9 * * MON-FRI means 09:00 on weekdays.
      • Reminder sequence: enter Offsets in minutes. 0, 1440, 4320 sends at the start, a day later and three days later.
    3. Optionally set Start, End (optional) and Max runs (optional).
    4. To skip weekends, tick Working days only (Mon–Fri). To skip holidays as well, choose a Holiday calendar.
    5. Under Notification, choose the Notification type or enter a Template code (optional), the Channels (empty = type default), and at least one of Recipient email, Recipient mobile and Recipient user id.
    6. Enter the Variables (JSON), then select Create schedule. The hub checks it with a dry run, then shows the next run.

    A holiday calendar has an effect only when Working days only (Mon–Fri) is ticked.

    What you seeWhat to do
    Invalid cron expression: …Check the five fields and their order.
    None of the requested channels could be addressed for the recipient(s).Add a recipient address that suits the channels.

    Managing schedules

    The table shows the pattern, time zone, next and last run, and the number of runs. Use Enabled to pause and restart a schedule. The braces icon (View request) shows what will be sent. The delete icon removes it, and future runs are cancelled.

    To change a schedule

    1. Select the edit icon on its row. The form below fills in, under the heading Edit and the schedule's name.
    2. Make your changes. The Company and Application cannot change: to move a schedule, delete it and create it again.
    3. Select Save changes. The hub checks it again with a dry run and shows the next run. Select Cancel to leave it as it was.

    Creating a holiday calendar

    1. Open Holiday calendars.
    2. Under New calendar, enter the Name and Country, and choose the Tenant. Only platform administrators can choose Platform-wide.
    3. Enter Dates (one per line: yyyy-mm-dd Name), such as 2027-01-26 Republic Day.
    4. Select Create calendar.

    Lines the hub cannot read are listed as Unrecognised lines: …, and the calendar is not saved.

    Changing or deleting a calendar

    1. To change one, select its edit icon, change the Name, Country or Dates (one per line: yyyy-mm-dd Name), then select Save changes. Schedules that use the calendar are rescheduled straight away, so a run on a new holiday moves.
    2. To delete one, select its delete icon and confirm with Delete. A calendar that a schedule uses cannot be deleted: choose another calendar for that schedule first.
