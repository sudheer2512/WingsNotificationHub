Part 4

Setup and administration

Connect providers, set up customers, applications and people, watch costs and system health, and keep a record of everything.

    Providers

    A provider account connects the hub to a service that carries messages. The hub chooses between accounts for each delivery and moves to another if one fails.

    Who can do this: platform, tenant and company administrators add, edit, test and suspend. Only a platform administrator can create a Shared (all tenants) account. Application administrators, operators and auditors read only.

    How the hub chooses a provider

    1. It looks at company accounts, then tenant accounts, then shared accounts, if the tenant allows them.
    2. It applies any routing rules, then drops accounts that are suspended, unhealthy, wrong for the destination country or over their monthly capacity.
    3. It picks by Priority (lower is preferred), then by cost.

    Sandbox applications use only Mock accounts.

    Adding a provider account

    1. Select Add provider.
    2. Enter a Name, and choose the Provider type and Channel. The type cannot be changed later.
    3. Choose the Scope: Tenant or Company, and which one. Platform administrators can also choose Shared (all tenants).
    4. Fill in Settings and Credentials from the provider's own console. Secrets are encrypted and never shown again.
    5. Under Routing & limits, set the Priority (lower is preferred), Fallback provider, Duplicate-risk policy and any limits.
    6. Tick Enabled, then select Save.

    Testing an account and setting its callback

    1. Select the account, then Test.
    2. Optionally enter an address in Send a test message to (optional). Leave it empty to check connectivity only.
    3. Select Run test. The result appears as Connectivity test:, green for healthy and red otherwise.
    4. Copy the Callback URL from the account details into the provider's console, so that delivery receipts, bounces and replies reach the hub.

    Adding a sender identity

    1. Select the account and go to Sender identities.
    2. Under Add sender, enter the address. The label fits the channel: From address, Sender id / number or Address.
    3. Enter a Display name, and limit it with Company (optional) if needed.
    4. Add the channel's details: Reply-to for email, DLT entity id for SMS in India, or Phone number id and Business account id for WhatsApp.
    5. Tick Default sender if it applies, then select Add sender.

    Use Suspend and Resume on a sender's row to stop and restart it at once.

    Pinning traffic with routing rules

    Routing rules send a channel to a chosen account, optionally for one country or message class. Without a matching rule, enabled healthy providers are tried by priority.

    1. Open the Routing rules tab.
    2. Choose the Channel and Provider.
    3. Choose the Tenant and Company. Platform administrators can choose Platform-wide.
    4. Optionally enter a Country prefix, such as +91, and choose a Message class. Set the Order.
    5. Select Add rule. Use the delete icon to remove a rule.

    Setting a fallback and suspending an account

    Select Edit on an account and set Fallback provider: if this account has an outage, the hub moves to that account for the same channel.

    To stop an account at once, select Suspend, enter a Reason and confirm. Traffic moves to other providers. Select Resume to bring it back. Both are audited.

    Changing credentials

    Credentials of an existing account are protected by maker-checker.

    1. Select the account, then Edit. Each stored secret shows •••••••• (stored).
    2. Enter a new value only for what is changing. Leave the rest empty.
    3. Select Save. You see Settings saved. Credential changes take effect after approval by another administrator.
    4. The account shows credential change pending, and the stored credentials stay in use.
    5. Another administrator opens Approvals and approves it. The new credentials then replace the old ones.

    Sender domain guidance

    For email to reach the inbox, your sending domain needs SPF, DKIM and DMARC records.

    1. Open the Sender domain guidance tab.
    2. Enter the Sender domain, such as mail.example.com, and select Show DNS records.
    3. Give the records to whoever manages your DNS. Replace the placeholders with your provider's values.

    Use a separate subdomain for bulk and promotional mail, and start DMARC at p=none while you watch the reports.

    Tenants and companies

    A tenant is a customer on the hub, and companies are the businesses inside it.

    Who can do this: only platform administrators create tenants. Tenant administrators add and edit companies and edit their tenant. Other roles see this screen read-only.

    Creating or editing a tenant

    1. Select + Tenant, or the pencil icon on a tenant's row.
    2. Enter the Code, which cannot be changed later, the Name and the Default time zone.
    3. Set Message body retention (days). After this many days message bodies are deleted and the record of delivery stays.
    4. Set Data retention (days), at least 30. After this many days delivery records are deleted.
    5. Choose Allow shared (platform) providers and Require marketing consent for promotional messages.
    6. Fill in Branding if you need it, then select Save.

    Creating or editing a company

    1. Select + Company, or the pencil icon on a company's row.
    2. Choose the Tenant, and enter the Code, Name, Country and Time zone (IANA), such as Asia/Kolkata.
    3. Under Quiet hours (recipient local time), tick Enabled, then set Start, End, Applies to and Channels (empty = all except in-app). For example, 21:00 to 08:00 for promotional messages.
    4. Fill in Branding to override the tenant's, then select Save.

    Messages inside quiet hours wait until the window ends. A rule can set its own quiet hours ().

    Applications and credentials

    An application is a system that sends through the hub. It signs in with a client credential, and can send only for the companies you link it to.

    Who can do this: platform and tenant administrators add and link applications. They and application administrators manage credentials.

    Adding an application

    1. Select + Application.
    2. Choose the Tenant, and enter the Code and Name.
    3. Choose Allowed channels (empty = all), the Default locale and the Rate limit (requests/min per credential).
    4. Tick Sandbox (messages are not sent to real providers) while it is being tested.
    5. Select Save, then switch on each company under Company links. An application can send only for companies it is enabled for.

    Creating and revoking a credential

    1. Select the application. Under New credential, enter a Name, such as Production ERP.
    2. Choose the Scopes. Remove any it does not need.
    3. Optionally choose Restrict to companies and Expires (optional).
    4. Tick AI agent (stricter policy; may need human approval per notification type) only for an AI agent.
    5. Select Create credential.
    6. Copy the Client id and Client secret, store them safely, and select I have stored it.

    The secret cannot be shown again. If it is lost or exposed, select Revoke and create a new credential. Revoking stops issued tokens within seconds and cannot be undone.

    Users and roles

    People get into the console through a user account and one or more role grants. Each grant has a scope: grant the narrowest that works.

    Who can do this: platform and tenant administrators. A tenant administrator cannot grant Platform administrator, or grant anything outside the tenant.

    Adding a user

    1. Under Add user, enter the Email and Display name.
    2. Enter a Password (min 12; empty = external OIDC). Leave it empty for someone who signs in through your organisation's identity provider.
    3. Choose the Role.
    4. Set the scope: Tenant, Company, Application and Channel. Leave All companies, All applications and All channels for the widest.
    5. Select Create user. Give the person their password by a safe route.

    Each email address can belong to one user only. If it is already in use you see A user with this email already exists. Use Grant on their row to add a role., and the existing account is not changed.

    Granting or removing a role

    1. To grant, select Grant on the person's row. The form changes to Grant a role to ….
    2. Choose the role and scope, then select Grant role. Select Add a different user to return to the blank form.
    3. To remove, select the × on the role and confirm with Remove.

    Changing an account

    1. To rename someone or set a new password, select the edit icon on their row. Change the Display name or enter a New password of at least 12 characters, then select Save. Leave the password empty to keep the current one.
    2. To stop someone signing in, select Disable and confirm. They are signed out at once. Their roles are kept, so Enable brings the account back as it was.

    These buttons appear only where you manage every role the person holds, so a tenant administrator cannot change a platform administrator or someone who also works in another tenant. You cannot disable your own account. Someone who signs in through your identity provider has no password here.

    Webhooks

    Webhooks tell your applications what happened, as it happens: a status changed, a notification finished, a customer replied. Each call is signed so the application can trust it.

    Who can do this: platform, tenant, company and application administrators.

    Registering a webhook

    1. Under Register webhook, choose the Application and, optionally, Company (optional).
    2. Enter a Name and the HTTPS URL of the application's endpoint.
    3. Choose the Event types, or All events (*).
    4. Select Register.
    5. Copy the Signing secret and give it to the application's developers. It is shown only once.
    Event typeSent when
    delivery.status_changedA delivery's status changes
    notification.completedAll of a notification's deliveries have finished
    inbound.message_receivedA customer replies
    push.interactionSomeone interacts with a push message
    inapp.actionSomeone acts on an in-app message
    notification.webhookA message is sent on the Webhook channel

    URLs must be https and cannot point to a private network, except on a development system set up to allow it.

    Testing and watching a webhook

    • Test sends a test event. You see Test event … queued, and the attempts list opens.
    • Attempts shows each call: time, event, Delivered or Failed, HTTP code, duration and error.
    • The delete icon stops events to that address.

    Failed calls are retried, up to 8 times with growing gaps. After 100 failures in a row the hub disables the webhook and raises an alert. Fix the receiver, then select Enable.

    Usage and billing

    See what was sent and what it cost, and set limits.

    Who can do this: everyone with this screen can read it: administrators, campaign managers and auditors. Tenant and platform administrators set quotas. Only platform administrators add credits or change rates.

    Reading usage

    Use the filters, then Group by: Channel, Application, Company, Provider or Month.

    Setting a quota

    1. Open the Quotas tab.
    2. Under Set quota, choose the Tenant, and optionally the Company, Application and Channel.
    3. Enter the Monthly limit and Alert threshold %.
    4. Select Save quota. Saving the same scope again updates it. Use the delete icon to remove one.

    A quota is a hard stop. Once it is reached, the hub refuses new sends with quota_exceeded, for example Monthly email quota for this company is exhausted (9/1). The application sees this error, and nothing appears in the explorer.

    Prepaid credits

    Without a credit account, sending is not limited by balance. With one, each account shows its Balance, reserved and available amounts, and a Low balance chip below its threshold. Open Recent transactions to see each movement.

    1. On the Credits tab, under Top up, choose the Tenant and Company, or Tenant-wide.
    2. Enter the Amount, an optional Low-balance threshold and a Note.
    3. Select Add credits. You see the new balance.

    Setting rates

    The Rates tab has two tables.

    • Customer billing rates set what customers pay. Choose the Tenant or Default (all tenants) and the Channel, then enter a Unit price (optional) or leave it empty to use cost plus Margin %. Select Save billing rate.
    • Provider cost rates set what providers charge. Choose the Channel and Provider, optionally a Country prefix and Message class, and enter the Unit cost. Select Add cost rate. Each rate takes effect from when it is added.

    3. Select a column heading to sort.
    4. Select CSV or Excel to download what the filters select.

    Requeuing a dead letter

    1. Find the item under Dead letters. Read Last error and fix the cause if you can.
    2. Select Requeue, then Requeue to confirm. You see Requeued.

    If it fails again, it returns to this list. Dead letters are kept for 30 days.

    The Requeue button appears only on items you can requeue. An auditor sees the item without the button. An item with no tenant, such as one queued before an upgrade, is visible only to platform administrators.

    Emergency suspension

    If something goes wrong, such as a compromised sender or a campaign sent in error, stop it here. Pending messages are held, not lost, and continue when you resume.

    Who can do this: platform, tenant and company administrators. Only a platform administrator can suspend a tenant.

    Suspending and resuming

    1. Open Emergency suspension. It lists Tenants, Companies, Applications and Active campaigns.
    2. Select Suspend on the row.
    3. Enter a Reason (audited). For a tenant, also tick I understand this stops all messaging for every company in the tenant.
    4. Select Suspend now. It appears under Currently suspended.
    5. When it is safe, select Resume, then Resume to confirm. Held messages continue.

    While a company is suspended, its applications are refused with The company is suspended. Every suspension raises a critical alert and is audited. Provider accounts and sender identities are suspended on the Providers screen ().

    Audit log

    Every change made in the console or through the API is recorded: who, what, when and where.

    Who can do this: auditors and platform, tenant and company administrators.
    1. Open Audit log.
    2. Filter with Action starts with, such as template., Entity type, such as NotificationTemplate or ProviderAccount, Entity id and From, plus Tenant if you see more than one.
    3. Select Search.
    4. Select a row to see the full entry.

    Each row shows the Time, Actor, Action, Entity, Summary, Scope and Correlation. Action names read like template.draft_saved, credential.created, company.suspended and credits.top_up. Addresses are masked in summaries.

    If someone quotes a correlation id from an error banner, it links their error to the actions around it.
