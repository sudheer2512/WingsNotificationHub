    Delivery status reference

    A delivery's status always moves forward. Not every channel reaches every status.

    StatusWhat it meansWhat to do
    DraftNot yet released for sending.Nothing.
    ScheduledWaiting for its send time, or for quiet hours to end.Nothing.
    QueuedWaiting for a worker.Nothing, unless many stay here.
    ProcessingA worker is handling it.Nothing.
    SubmittedHanded to the provider.Nothing.
    Provider acceptedThe provider took it.Nothing. Some providers report no further.
    SentThe provider says it left for the recipient.Nothing.
    DeliveredConfirmed as delivered.Nothing.
    ReadThe recipient opened it, on channels that report this.Nothing.
    Retry pendingA try failed, and another is scheduled.Wait, or select Retry.
    FailedIt could not be delivered.Read the failure, fix it, select Retry.
    ExpiredIts time limit passed before it could be sent.Retry if still useful.
    CancelledStopped before sending, for example with a campaign.Nothing.
    SuppressedBlocked by consent, preference or the suppression list.See .
    UnknownNobody can tell whether the provider took it.Select Resolve. See .

    Template syntax reference

    Templates use a small, safe language. Output is always escaped, and no code can run.

    Variables

    WriteMeaning
    {{CustomerName}}A variable. Names ignore case.
    {{Customer.Name}}A value inside another value.
    {{CompanyName}}, {{TenantName}}, {{RecipientName}}, {{UnsubscribeUrl}}, {{CurrentDate}}Built-in: the hub supplies these when sending.

    Filters

    Filters follow a |, can be chained, and take one argument after a :.

    FilterExampleResult
    upper{{CustomerName | upper}}UPPER CASE
    lower{{Email | lower}}lower case
    title{{CustomerName | title}}Title Case
    trim{{Comment | trim}}Removes surrounding spaces
    default:text{{Nickname | default:Customer}}Fallback when empty
    truncate:n{{Comment | truncate:80}}Cuts to n characters (…)
    number:decimals{{Quantity | number:2}}Grouped number
    currency:code{{InvoiceAmount | currency:INR}}Currency amount, such as ₹1,84,500.00
    date:format{{DueDate | date:dd-MMM-yyyy}}Date, such as 12-Nov-2026
    url{{PaymentLink | url}}Safe http(s) link only

    Blocks

    WriteMeaning
    {{#if Discount}}Save {{Discount}}{{else}}No offer{{/if}}Conditional section
    {{#unless Paid}}Payment pending{{/unless}}Inverse conditional
    {{#each Items}}{{@index}}. {{this.Name}}{{/each}}Repeat for each list item
    {{! internal note }}Comment, not rendered

    Every {{#if}}, {{#unless}} and {{#each}} needs its closing tag. While a block is unclosed, Live preview says so, for example Unclosed '#if' block (line 1, column 4).

    Troubleshooting

    A message wasn't delivered: what do I check?

    1. Find it. In the Notification explorer, enter the full address in Recipient (exact email or phone). Clear any date filters.
    2. Nothing found? The request never reached the hub, or the application got an error. Ask the application's owner. Check Emergency suspension and Quotas, which stop sends before they are recorded.
    3. Suppressed? Read the reason. See . A retry will not help until consent or the suppression changes.
    4. Failed? Read Failure and the Attempts tab. A bad address must be corrected. A provider fault can be retried once it recovers.
    5. Unknown? Check with the provider, then Resolve.
    6. Queued or Scheduled for a long time? Check the Attempts line on the delivery, which shows when the next try is due, quiet hours on the company, and queues and workers on System monitoring.
    7. Delivered, but the person says it didn't arrive? Ask them to check spam or blocked senders. For email, check Sender domain guidance. Quote the provider message id to the provider.

    Common error messages

    Errors appear in a red banner, with the code and a correlation id.

    MessageWhat it means
    Invalid email or password.Sign-in failed. Check both, or ask your administrator.
    You do not have access to this resource.Your role cannot do this. Ask an administrator.
    The notification could not be rendered.A required template variable is missing.
    None of the requested channels could be addressed for the recipient(s).The recipient has no address for the chosen channels.
    The template is invalid. body: Template HTML contains a disallowed constructRemove the script, event handler, frame or javascript: link.
    The rule is invalid.The message lists what to complete.
    Invalid cron expressionCheck the five fields of the schedule.
    Passwords must be at least 12 characters.Enter a longer password.
    A user with this email already exists.Select Grant on the person's row to add a role.
    … schedule(s) use this calendar.Choose another calendar for those schedules, then delete it.
    The provider account does not support template submission.Choose a real WhatsApp account, not a Mock one.
    An unexpected error occurred.Something failed inside the hub. Quote the correlation id to support.

    For developers and installers

    Everything in the console is also available through a REST API at /api/v1. A full, generated reference is linked as API reference at the foot of the menu.

    Sending a notification

    # 1. Get a token with a client credential from Applications
curl -X POST https://hub.example.com/connect/token \
  -d grant_type=client_credentials -d client_id=$ID -d client_secret=$SECRET

# 2. Send
curl -X POST https://hub.example.com/api/v1/notifications/send \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -H "Idempotency-Key: invoice-10045-created" \
  -d '{ "companyId": "<company id>",
        "notificationType": "INVOICE_CREATED",
        "recipient": { "customerId": "CUST-1001" },
        "channels": ["email", "whatsapp"],
        "variables": { "CustomerName": "ABC Traders", "InvoiceNumber": "INV-10045",
                       "InvoiceAmount": "18400", "InvoiceDate": "2026-11-06" } }'
# 202 Accepted: { "notificationId": "…", "status": "accepted", "deliveries": [ … ] }

    Publishing a business event for rules

    curl -X POST https://hub.example.com/api/v1/events \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{ "companyId": "<company id>", "eventType": "payment.overdue",
        "payload": { "customer": { "customerId": "CUST-1001" }, "DaysOverdue": 12 } }'

    Glossary

    Application
    A system that sends through the hub.
    Approval
    A second person's decision on a change. See maker-checker.
    Attempt
    One try at handing a delivery to a provider.
    Campaign
    One message sent to many recipients at a controlled pace.
    Channel
    Email, SMS, WhatsApp, in-app, push, web push or webhook.
    Circuit breaker
    Automatic rest for a provider that keeps failing.
    Client credential
    The id and secret an application uses to sign in.
    Company
    A business inside a tenant.
    Consent
    A recorded agreement to receive messages for a channel and purpose.
    Correlation id
    A reference linking an error or request to its records.
    Cron expression
    Five fields that describe a repeating time.
    Dead letter
    An item that used up its retries in a queue.
    Delivery
    One message to one address on one channel.
    DLT
    India's telecom registry for SMS senders and templates.
    E.164
    The full international phone format, such as +919845012345.
    Escalation
    A follow-up message when the first is not acted on in time.
    Event
    Something an application reports, such as payment.overdue.
    Fallback
    A second channel or provider used when the first fails.
    Hard bounce
    A permanent email delivery failure.
    Locale
    A language code, such as en or hi.
    Maker-checker
    The rule that the person who asks cannot also approve.
    Message class
    Transactional, promotional or critical.
    Notification
    One request to tell someone something.
    Notification type
    A named kind of message with its defaults.
    Payload
    The data sent with an event.
    Provider
    The outside service that carries a message.
    Quiet hours
    Times when chosen messages wait, in the recipient's local time.
    Quota
    A monthly limit on messages.
    Retention
    How long message bodies and records are kept.
    Rule
    Turns an event into notifications.
    Sandbox
    An application mode that never reaches real providers.
    Scope
    On a role, what it covers. On a credential, what it allows.
    Segment
    A filter that selects contacts for a campaign.
    Sender identity
    The address or number a message goes out under.
    Suppression
    A block on an address.
    Template
    The wording of a message, versioned and approved.
    Tenant
    A customer organisation on the hub.
    Throttle
    The most messages a campaign sends per minute.
    Webhook
    A signed call from the hub to an application.
